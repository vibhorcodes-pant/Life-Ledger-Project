1. Problem Statement & Objectives

BRD & PRD Grounding

⚠️ The Fragmented Wellness Problem

  • Siloed Applications: Users juggle separate apps for calorie tracking, water intake, daily habits, workouts, and sleep.
  • Tracking Friction: Switching contexts causes user abandonment and inconsistent data logging.
  • Lack of Holistic Correlations: No single platform correlates sleep quality with habit consistency or daily productivity.
  • Data Opacity: Existing commercial tools conceal user data storage without local or export transparency.

🎯 Life Ledger Solution & Objectives

  • Centralized Single Dashboard: Consolidate food diary, hydration, steps, sleep, exercise, and habits into one unified system.
  • Daily Date-Driven Logging: Instant navigation across history to review trends and personal consistency.
  • Reliable Dual Persistence: Local in-memory H2 database with direct JDBC operations and Spring Data JPA.
  • Cross-Platform Interfaces: Modern responsive web dashboard (React) + standalone desktop companion (Java Swing).

4. Rubric 1: OOP Implementation

Rubric: 10 Marks
Polymorphism & Interfaces

MetricCalculator Strategy Pattern

The system defines an interface MetricCalculator implemented polymorphically across distinct health dimensions:

  • ActivityMetricCalculator: Scores steps & workout time
  • HydrationMetricCalculator: Scores fluid volume
  • SleepMetricCalculator: Analyzes 7-9h optimal sleep window
  • NutritionMetricCalculator: Calculates caloric balance
for (MetricCalculator calc : metricCalculators) {
  scoreSum += calc.calculateScore(entry);
}
Inheritance & Exception Handling

Domain Hierarchy & Custom Errors

  • Inheritance: WellnessEntry extends BaseEntity to inherit automated timestamp auditing (createdAt, updatedAt).
  • Custom Exceptions:
    • ResourceNotFoundException → 404 Not Found
    • InvalidEntryException → 400 Bad Request
    • DatabaseOperationException → 500 DB Error
  • Global Handler: Centralized GlobalExceptionHandler ensures consistent error contracts.

6. Rubric 3: Multithreading & Concurrency

Rubric: 4 Marks
Backend Async Thread Pool

AsyncAnalyticsService (@Async)

Heavy trend analysis across historical logs is offloaded to a dedicated worker thread pool via Spring's @Async and CompletableFuture.

  • Configured with 4 core threads, scaling to 8 threads under load.
  • Prevents blocking HTTP request handling threads.
  • Non-blocking responsive client experience.
Thread Synchronization & GUI Worker

Thread Safety & SwingWorker

  • Critical Section Locks: Shared analytics metric counters protected via synchronized blocks and AtomicLong to avoid race conditions:
    synchronized (calculationLock) {
      totalCalculationsPerformed++;
    }
  • GUI Background Thread: Standalone Java Swing client employs SwingWorker<List<WellnessEntry>, Void> for async JDBC querying, keeping the UI at 60 FPS without freezing.

7. Rubric 4: Database Integration (JDBC & JPA)

Rubric: 8 to 10 Marks
Native JDBC Implementation

JdbcWellnessDao Class

Direct low-level database operations written strictly with pure java.sql.* JDBC:

  • Connection Management: Acquired via javax.sql.DataSource pool with auto-close try-with-resources.
  • SQL Injection Prevention: Parameterized PreparedStatement for all queries and inserts.
  • ResultSet Mapping: Manual parsing of column fields to instantiate domain objects.
  • Batch Execution: ps.addBatch() and ps.executeBatch() for child food and habit records.
Spring Data JPA & H2 Database
